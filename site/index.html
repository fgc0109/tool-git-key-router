复杂的身份配置，
变成清晰的路由规则

不用逐个修改仓库，也不用记住哪个项目该用哪把密钥。GitKeyRouter 把服务、命名空间和身份之间的关系变成可查看、可测试的配置。

多服务、多身份路由

支持 GitHub、GitLab、Gitea、Gogs、OneDev、GitBucket 与通用 Git 服务。服务默认身份、Owner、Namespace 和 Repository 精确规则按最长前缀生效。

github.com/camus0109/*→github-camus git.policoil.top/project-base/*→gitea-cloud

先预览，再应用

SSH Config、Git rewrite 和 Git Profiles 都先展示 diff 或结构化计划。外部状态变化时拒绝陈旧计划。

Git Profiles

按目录或远程 URL 自动选择提交姓名、邮箱与签名密钥，基于 Git 官方 includeIf，不侵入仓库配置。

备份健康管理

校验 manifest 与 SHA-256，将快照分类为完整、未完成、损坏或不支持。异常清理先预览并再次复核。

GUI 与 CLI

桌面界面和自动化命令共享同一服务图。诊断、解析、预览和测试命令可以安全用于脚本与 DevRunner。

GitHub CLI 身份路由

根据仓库 SSH HostAlias 自动选择独立的 GH_CONFIG_DIR，核验实际 API 账号，并以身份级共享/独占锁阻止并发串号。

HOW IT WORKS

Git 负责改写，SSH 负责选密钥

GitKeyRouter 不创造私有协议，只是把 Git 和 OpenSSH 已有能力连接起来。

  1. 01

    定义身份

    为每个 Git 服务配置 HostAlias、账号和本地密钥路径。

  2. 02

    定义路由

    把服务默认规则或具体 Namespace / Repository 指向对应身份。

  3. 03

    应用并验证

    预览 SSH Config 与 insteadOf，创建快照后精确写入并复核结果。

仓库 URLhttps://host/owner/repo.git
→
Git insteadOfgit@host-alias:owner/repo.git
→
SSH HostAliasIdentityFile ~/.ssh/id_account
SAFE BY DEFAULT

配置工具更应该
尊重你的机器

每个写入边界都经过明确设计：不拼接 shell 命令、不覆盖整份 Git 配置、不显示私钥正文，不把失败伪装成成功。

查看安全策略 →
  • 01
    崩溃恢复

    Git Profile 应用前持久化事务日志；进程中断后先恢复原始文件与 include 顺序。

  • 02
    并发保护

    单实例写入锁配合文件 SHA-256 与 rewrite 计划令牌，拒绝覆盖外部修改。

  • 03
    失败回滚

    Git rewrite 的删除、添加、验证或配置保存失败都会恢复受影响的精确值。

  • 04
    日志脱敏

    私钥块、URL 凭据、Bearer、ASKPASS 和常见 Token 在落盘前统一清理。
