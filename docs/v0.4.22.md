# GitKeyRouter v0.4.22 开发记录

## 目标

解决“GitKeyRouter 内的 OpenSSH 测试成功，但 Git for Windows 的 `clone` / `ls-remote` 仍失败”的诊断断层，并为首次连接的 SSH 服务器增加可核验、可回滚的主机密钥信任流程。

## 根因边界

GitKeyRouter 生成的 `HostAlias`、`IdentityFile` 和 `known_hosts` 都属于 OpenSSH 配置。PuTTY/Plink 使用另一套配置、主机密钥存储和参数协议；因此手工执行 `ssh -vT` 成功，不代表配置为 PuTTY/Plink 的 Git 会使用同一身份。

## 已完成范围

- 同时检查 `GIT_SSH_COMMAND`、`GIT_SSH`、`GIT_SSH_VARIANT`、`core.sshCommand` 和 `ssh.variant`。
- 在无显式设置时，让 Git 对本机拒绝端口构造一次无外网 SSH 调用，并从 Git trace 判断实际启动的是 OpenSSH 还是 Plink。
- 概览和一键诊断把 PuTTY/Plink 作为不兼容错误，不再把后续失败误判为私钥、路由或密码问题。
- GUI 的 `git ls-remote` 测试在联网前检查后端；配置型 PuTTY/Plink 可在确认 diff 后写入全局 `core.sshCommand` 和 `ssh.variant=ssh`，环境变量覆盖则明确阻止无效修复。
- 新增 `ssh-backend [--use-openssh --yes]`，支持只读检查、修复预览和显式确认写入；失败时恢复先前全局值。
- OpenSSH 首次连接失败时使用 `ssh-keyscan` 扫描服务端公钥，展示 SHA-256 指纹并要求用户通过可信渠道核验。
- 只向 `%USERPROFILE%\.ssh\known_hosts` 追加已确认的密钥；已有冲突时拒绝自动覆盖，不使用 `StrictHostKeyChecking=no`。
- 写入前重新扫描并复核服务端指纹和文件 SHA-256；已有文件先建立唯一备份，写入验证失败时恢复原文件或删除新建文件。
- Git rewrite、Git 服务和身份测试在安全信任后自动重试。
- 新增 `trust-host <id-or-host> [--yes]`，CLI 默认只展示指纹，显式确认后才写入。

## 安全与兼容边界

- 不支持把 PuTTY/Plink 配置直接转换为 OpenSSH 配置；程序只切换 Git 的 SSH 执行后端，不读取 PuTTY 注册表主机缓存或 PPK 私钥正文。
- `GIT_SSH_COMMAND`、`GIT_SSH` 或 `GIT_SSH_VARIANT` 的环境覆盖优先级高于 Git 全局配置。检测到不兼容覆盖时必须在外部删除/修正并重启程序。
- 未知自定义 SSH 包装器不会被自动替换。
- `ssh-keyscan` 只能取得服务器当前提供的公钥，不能独立证明服务器身份；用户仍须通过管理员或其他可信渠道核验指纹。
- 已有 `known_hosts` 冲突可能代表服务器换钥或中间人攻击，必须人工确认，程序不会删除旧记录。
