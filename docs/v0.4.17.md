# GitKeyRouter v0.4.17 开发记录

## 目标

让 GitHub CLI API 身份与 GitKeyRouter 已选择的 SSH 身份保持一致，同时避免使用进程全局的 `gh auth switch`。

## 已完成范围

- 新增 `gh-login`、`gh-status` 和透明的 `gh [--identity ...] -- ...` CLI 边界。
- 根据显式身份、`-R/--repo`、当前分支跟踪 remote、`remote.pushDefault` 或 `origin` 解析 GitHub 身份。
- 从 Git 展开的 push URL 读取 SSH HostAlias，并要求 HostAlias、仓库路由和目标身份一致；多身份 remote 或歧义配置会失败关闭。
- 为每个稳定身份 ID 派生独立 `GH_CONFIG_DIR`，并把解析出的 GitHub Host 和仓库绑定到单个 `gh` 子进程。
- 移除继承的 `GH_TOKEN`、`GITHUB_TOKEN`、企业 Token 和无关仓库覆盖，阻止包装执行会改变账号选择的 `gh auth/config/alias` 命令。
- 浏览器登录后通过 `gh api user --jq .login` 反查真实账号；账号不符或 `hosts.yml` 出现明文 `oauth_token` 时拒绝继续。
- 要求 GitHub CLI 2.40.0 或更高版本，避免旧版同 Host 单账号凭据模型导致身份相互覆盖。
- 为外部进程增加继承控制台模式，保留交互输入、实时输出和原始退出码，同时不把转发参数或输出写入 GitKeyRouter 日志。

## 安全与备份边界

- GitKeyRouter 不读取、保存或记录 Token；OAuth 与系统凭据存储仍完全由 GitHub CLI 负责。
- GitHub CLI 配置目录不进入普通快照或 `.gkrbackup` 便携包；迁移电脑后需要按身份重新登录。
- `gh-login` 使用身份级文件锁；普通 API 命令依靠独立进程环境，不修改全局活动账号。
