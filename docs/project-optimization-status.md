## 最初 8 项计划的完成情况

| 原计划 | 当前状态 | 当前证据与剩余边界 |
|---|---|---|
| 1. Git Profile 应用事务性 | **完成** | `GitProfileService` 在正式写入前持久化全部受影响文件和原 `include.path` 顺序；独占启动会恢复被中断的 `applying` 事务，恢复失败时保留日志并阻止新写入。 |
| 2. 预览后应用冲突检测 | **完成** | SSH Config、Git Profile、普通应用配置和 Git Rewrite 计划均携带创建时状态；受影响状态变化会在写入前拒绝，Rewrite 计划外 key 变化不阻断。 |
| 3. Git URL Rewrite 自动回滚 | **完成** | 应用时捕获受影响 key，任一删除、添加、验证或配置保存失败都会恢复原值并复核；应用错误和回滚错误分别报告，计划外 key 不参与写入。 |
| 4. 保守/严格 SSH 同步 | **完成** | 保守同步保留孤儿 managed block；严格同步只删除完整 GitKeyRouter 标记的孤儿块，保留普通 Host、注释和不完整标记，并通过 diff 与确认执行。 |
| 5. 备份目录原子完成 | **完成** | 快照原子发布；健康清单分类全部直接子目录并验证完整性；异常清理具备预览、根目录/重解析点/活动 pending 保护和执行前复核。 |
| 6. 子进程输出与终止诊断 | **完成** | stdout/stderr 和单行长度受限；启动失败、取消、超时、终止失败可以区分；专用 helper 以 ready 握手确定输出、挂起和子进程树状态，已移除 shell、ping 和 100 ms 猜测。 |
| 7. 日志敏感信息脱敏 | **完成** | 私钥块、URL 凭据、Bearer、secret/Token/ASKPASS 赋值及 GitHub/GitLab 前缀 Token 均在写盘前处理，并以普通 URL、路径、公钥/指纹和提交 SHA 反例控制误报。 |
| 8. 工程维护增强 | **部分完成** | CI 已有 locked restore、格式、Release 构建和测试；两种 Windows 单文件产物及 CLI 版本冒烟已覆盖；xUnit v3 和中央包管理已落地。覆盖率门禁、推荐分析器清理、SBOM、provenance 和 Authenticode 尚未完成。 |

## 未完成需求的重新规划

后续继续采用“一个需求一个补丁版本、每个版本 1–2 个提交”的边界。v0.4.18–v0.4.20 已依次完成解析可解释性、身份档案生命周期，以及透明执行和跨进程隔离；v0.4.21 增加安装器交付；v0.4.22 修复 Git 实际 SSH 后端与 OpenSSH 路由、主机信任之间的运行时断层；v0.4.23 交付安全应用更新。

### 第三阶段 A：崩溃与并发安全

#### v0.4.10：Git Profile 可恢复持久化事务（开发完成）

实现为 1 个完整提交：`fix(profiles): persist recoverable application transactions`。

验收：事务目录持久化所有受影响文件、存在状态、SHA-256、原 `include.path` 顺序和状态机；正式写入前落盘并回读 `applying`；启动时回滚 `applying` 事务并清理未进入正式写入的 `prepared` 事务；成功提交或回滚后安全清理；覆盖成功恢复、日志篡改和恢复失败重试测试。

#### v0.4.11：配置与 Rewrite 计划乐观并发保护（开发完成）

实现为 2 个提交：

1. `fix(config): add optimistic concurrency to configuration saves`
2. `fix(preview): reject stale Git rewrite plans`

验收结果：复合配置操作携带配置文件存在状态和 SHA-256；Rewrite 计划记录生成时全部受影响 key 的精确有序值；应用前和备份后重新比较，受影响状态变化即拒绝执行；计划外 key 的变化不阻断、不写入也不回滚；已覆盖顺序变化、外部修改和配置文件替换测试。

#### v0.4.12：备份健康清单与安全清理（开发完成）

实现为 1 个完整提交：`feat(backup): manage snapshot health and safe cleanup`。

验收结果：完整、pending、损坏、未知版本分别展示原因、文件和完整性；清理仅允许位于备份根目录下且不属于活动/近期事务的异常目录；清理前展示目标，执行前和清理后重新扫描；路径逃逸、重解析点、近期 pending、目标变化和删除失败均有测试。
