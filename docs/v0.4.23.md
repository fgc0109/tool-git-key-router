# GitKeyRouter v0.4.23 开发记录

## 目标

把已经在 `main` 完成的安全应用更新流程作为新版本正式交付，让已安装 v0.4.22 的用户能够取得更新器，并在后续稳定版本中使用应用内检查与 MSI 覆盖升级。

## 已完成范围

- GUI 默认在启动后检查更新，并提供可持久化的开关和手动“检查更新”入口。
- 优先读取 GitHub Pages 的 Schema 3 更新清单，失败时回退到 GitHub Releases API；两条路径都只接受稳定数字版本。
- 校验发布页、安装包和校验清单均来自官方仓库的规范 HTTPS 路径，拒绝外部主机、非规范资产名和版本不一致。
- 根据 MSI 注册信息和当前进程路径识别自包含或依赖框架安装版；便携版不尝试运行中覆盖自身。
- 下载过程限制校验清单与安装包大小、设置总超时、写入 `.partial` 文件，并对 `SHA256SUMS.txt` 中唯一同名条目进行流式 SHA-256 校验。
- 安装版使用独立维护程序等待精确的父进程实例退出，重新校验 MSI 后以 Windows Installer 完成覆盖升级、记录结果并重启应用。
- 两种 MSI 均包含一个自包含 `GitKeyRouter.Updater.exe`；安装器结构测试验证更新器负载，便携 ZIP 继续保持单文件边界。
- Release 成功后由 Pages 工作流生成 `site/update.json`，避免清单先于正式资产发布。

## 安全与兼容边界

- v0.4.22 本身没有更新器，因此必须先通过 MSI 或便携 ZIP 手动升级到 v0.4.23。
- 自动安装只适用于当前进程确实位于受登记 MSI 安装目录、安装类型匹配且独立更新器存在的情况。
- 更新器使用系统目录中的 `msiexec.exe` 并触发正常的 Windows UAC；程序不会绕过管理员授权。
- 下载地址限制为 `project-base-mirror/tool-git-key-router` 的官方 Release；校验失败、重复校验项、超限下载或安装失败均停止流程。
- 便携版只打开经过校验的官方 GitHub 页面，不实现自替换，也不会静默删除用户现有便携文件。
