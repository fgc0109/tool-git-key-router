# GitKeyRouter v0.4.25 开发记录

## 目标

修复 MSI 覆盖升级后任务栏固定项可能显示白纸图标的问题，使开始菜单和桌面快捷方式不再绑定旧 ProductCode 的 Windows Installer 图标缓存。

## 根因

v0.4.21–v0.4.24 的开始菜单快捷方式使用 `Advertise="yes"`，并且开始菜单、桌面快捷方式都显式引用 MSI Icon 表中的 `GitKeyRouterIcon.exe`。覆盖升级会生成新的 ProductCode，并在卸载旧产品时删除旧的 `C:\Windows\Installer\{ProductCode}\GitKeyRouterIcon.exe`；已有任务栏固定项仍引用旧缓存，因此显示白纸图标。

## 已完成范围

- 开始菜单快捷方式改为独立生命周期组件和非广告快捷方式，直接指向 `[APPLICATIONFOLDER]GitKeyRouter.exe`。
- 桌面快捷方式继续直接指向主程序，并移除显式 MSI Icon 引用。
- 顶层 Icon 表资源与 `ARPPRODUCTICON` 保留，仅继续服务于 Windows“已安装的应用/程序和功能”图标。
- MSI 结构校验检查两个快捷方式的直接 EXE 目标、空 Icon/Arguments、开始菜单独立组件及 HKCU Registry KeyPath。
- 安装器生命周期测试启用两个快捷方式，并在旧版升级到新版后读取真实 `.lnk`，检查目标为当前安装目录的 EXE、图标不引用 `C:\Windows\Installer`，卸载后快捷方式被删除。
- 安装器构建在每次运行前清理两个受控 WiX 中间目录，避免连续构建不同版本时复用旧版本输出文件名。

## 兼容边界

- 已经损坏的旧任务栏固定项仍需取消固定并从新版开始菜单重新固定一次；本修复保证此后新固定项不再依赖旧 ProductCode 的图标缓存。
- 不保留广告快捷方式或双路径兼容分支，安装包只有直接 EXE 快捷方式这一条生产路径。
- `ARPPRODUCTICON` 不参与任务栏固定项，保留它不会重新引入该问题。

## 验收状态

- 两种 0.4.25 测试 MSI 已在全部 ICE 校验启用时以 0 警告、0 错误生成。
- 完整测试 306/306 通过，Release 构建 0 警告、0 错误。
- 自包含与依赖框架的便携发布物均通过启动验证；两种 MSI 均成功生成并通过数据库结构校验。
- 已验证先构建 0.4.25 测试包、再构建当前 0.4.24 正式版本时不会复用旧版本 WiX 输出文件名。
- 提权生命周期脚本已覆盖 v0.4.24 安装、升级、真实快捷方式和卸载清理；本机实际执行需要管理员权限，本轮 UAC 未获授权，因此不把真实安装生命周期标记为已通过。
