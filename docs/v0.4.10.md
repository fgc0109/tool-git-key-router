# GitKeyRouter v0.4.10 开发记录

## 版本目标

让 Git Profile 应用在进程崩溃、系统断电或强制退出后仍可恢复，不再只依赖方法返回前的内存回滚。

## 实现范围

- 在 `%APPDATA%\GitKeyRouter\git-profile-transactions` 持久化独立事务日志。
- 日志记录所有受影响文件的原始存在状态、内容、SHA-256，以及全局 `include.path` 的精确顺序。
- 状态机区分 `prepared`、`applying`、`committed` 和 `rolled-back`；正式修改前必须持久化并回读 `applying`。
- GUI 与确认写入 CLI 取得排他锁后，先恢复被中断的 `applying` 事务，再开始新工作。
- 恢复失败时保留事务日志并阻止新的写入；提交或回滚成功后安全清理。
- 日志路径限制在 Git Profile 托管目录中，并在恢复前验证重复路径、内容和 SHA-256。

## 测试与失败语义

- 验证成功应用后不遗留事务目录。
- 验证持久化 `applying` 日志可恢复被覆盖、被新建的 Profile 文件和原始 `include.path` 顺序。
- 验证日志被篡改时不修改当前文件或 Git 配置。
- 验证恢复失败后保留 `applying` 日志，供下一次启动重试。
